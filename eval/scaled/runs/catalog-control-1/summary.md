## Summary

Added a disk-based fallback to `CatalogRepository.find`: when a product id is not present in the in-memory `store`, the method now calls the private helper `loadFromDisk(id)`, which reads `/var/cache/<id>` using `java.nio.file.Files.readAllLines`. The file is expected to contain a single line in `name,priceCents` format; any `IOException` (missing or unreadable file) or `NumberFormatException` (malformed price) is caught and silently returns `Optional.empty()`, so callers see the same "not found" result as before. No other classes were changed, so `CatalogService`, `CatalogController`, and the rest of the codebase are unaffected by this addition. Reviewers should note that the disk path is constructed directly from the caller-supplied `id`, so ids containing path-separator characters (e.g. `../`) would traverse outside `/var/cache`; if ids can come from untrusted input, a sanitisation check on `id` should be added before production use.
