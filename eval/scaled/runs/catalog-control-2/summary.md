## Summary

Added a disk-based fallback to `CatalogRepository.find`: on a cache miss (id absent from the in-memory `store`), it now reads `/var/cache/<id>` using `java.nio.file.Files.readAllLines`, parses the first line as `name,priceCents`, constructs a `Product`, and returns it wrapped in `Optional`. If the file is missing, unreadable, or the line cannot be parsed (wrong format or non-integer price), the method catches the `IOException` or `NumberFormatException` and returns `Optional.empty()`, preserving the "not found" contract. No new dependencies were introduced — only standard JDK `java.nio.file` APIs. The rest of the codebase (`CatalogService`, `CatalogController`, etc.) requires no changes since they already consume `Optional<Product>` from `find`. Reviewers should note that the file path is constructed directly from the caller-supplied `id` string with `Path.of("/var/cache", id)`, which resolves safely for simple id strings but ids containing path separators could allow directory traversal in a production context.
