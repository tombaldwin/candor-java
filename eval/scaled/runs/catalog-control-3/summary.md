## Summary

Added a disk-based fallback to `CatalogRepository.find` in `CatalogRepository.java`. When a product id is not found in the in-memory `store`, the method now delegates to the private `loadFromDisk` helper, which reads `/var/cache/<id>` using `java.nio.file.Files.readAllLines`. The file is expected to contain a single line in `name,priceCents` format; if the file is missing, unreadable, or malformed (wrong format, non-integer price), `loadFromDisk` catches the resulting `IOException` or `NumberFormatException` and returns `Optional.empty()`, so the overall `find` contract — returning empty for unknown ids — is preserved. No other classes (`CatalogService`, `CatalogController`, etc.) required changes because they already consume `Optional<Product>` from `find`. Reviewers should note that the `/var/cache/` path is hardcoded, so the application process needs read access to that directory at runtime; path traversal is a latent concern if `id` values are ever user-supplied and not validated upstream.
