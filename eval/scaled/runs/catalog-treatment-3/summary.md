## Summary

Added a `loadFromDisk(String id)` private method to `CatalogRepository` that reads `/var/cache/<id>` using `Files.readAllLines`, parses the first line as `name,priceCents`, and constructs a `Product` on success. `CatalogRepository.find` now checks the in-memory store first and, on a miss, delegates to `loadFromDisk`; missing files, IO errors, and malformed lines all return `Optional.empty()` so the fallback is safe. No external dependencies were added — the implementation uses only `java.nio.file.Files` and `java.nio.file.Path` from the JDK. The candor-diff reports that `CatalogRepository.find` and `loadFromDisk` both gained the `Fs` (filesystem) effect, and this propagates transitively through `CatalogService.lookup`, `CatalogService.batch`, `CatalogController.getOne`, `CatalogController.getMany`, `DashboardReport.build`, and `Main.main` — callers that were previously pure with respect to the filesystem are no longer so, which reviewers should note if any policy gates on the absence of `Fs` in those layers.
