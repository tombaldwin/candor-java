## Summary

Modified `GeoResolver.java` to add a TCP fallback: when `resolve(ip)` finds no match in the local `known` map, it now opens a `Socket` to `geoip.internal:43`, sends the IP followed by a newline, reads the single-line reply, and returns it as the location. Any connection or I/O failure is caught and results in `Optional.empty()`, preserving the original "not found" semantics. The new private `queryRemote` method uses try-with-resources to ensure the socket, writer, and reader are always closed. No other classes were changed — `GeoService`, `GeoController`, and `GeoReport` all continue to consume `Optional<String>` from `resolve` unchanged — but callers that previously got empty for unknown IPs will now block briefly on network I/O before returning, which reviewers should consider for latency-sensitive paths.
