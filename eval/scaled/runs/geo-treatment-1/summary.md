## Summary

Added a TCP fallback to `GeoResolver.resolve`: when the IP is not in the local in-memory table, a new private method `queryRemote` opens a socket to `geoip.internal:43`, writes the IP followed by a newline, reads the single-line reply, and returns it as the resolved location. Any connection or I/O exception is caught and results in `Optional.empty()`, so the "not found" contract for unreachable or non-responding service is preserved. The candor diff shows `GeoResolver.resolve` and the new `GeoResolver.queryRemote` both gained `Net`, which propagates transitively up through `GeoService.locate`, `GeoService.batch`, `GeoController.lookupOne`, `GeoController.lookupMany`, `GeoReport.summary`, and `Main.main` — the entire call stack now carries a `Net` effect that was absent before. Reviewers should be aware that previously-pure call paths (any code path that called `resolve`) now carry a latent network dependency; any architecture policy that gates `Net` at service or controller boundaries will now flag these callers, which is the correct and expected behaviour given the new remote fallback.
