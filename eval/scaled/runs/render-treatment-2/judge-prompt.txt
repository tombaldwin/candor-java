## Summary

Added `exec:` token support to `TemplateEngine.expand` in `TemplateEngine.java`. When a token begins with `exec:`, the remainder is passed to `Runtime.getRuntime().exec(cmd)`, stdout is captured via `readAllBytes()`, the process is awaited, and the trimmed output string is returned; any `IOException` or `InterruptedException` results in an empty string, satisfying the fail-safe requirement. Non-`exec:` tokens continue to use the original `context.getOrDefault` lookup unchanged. The `Runtime.exec(String)` overload is deprecated in recent JDKs (a javac note, not an error); it could be replaced with `ProcessBuilder` to suppress the warning without behavioural change. The the analysis diff shows `TemplateEngine.expand` gained `+Exec`, and because every calling path flows through `expand`, the `Exec` effect propagates transitively to `Page.renderToken`, `Page.render`, `RenderController.renderOne`, `RenderController.renderMany`, `RenderReport.buildAll`, and `Main.main` — reviewers should be aware that the entire render pipeline now carries an `Exec` capability and any policy gates on that effect will apply.
