## Summary

Added `exec:` token support to `TemplateEngine.expand` in `TemplateEngine.java`: when the token starts with `exec:`, the remainder is passed to `Runtime.getRuntime().exec()`, the standard output is read via `getInputStream().readAllBytes()`, trimmed, and returned; any `IOException` (command not found, etc.) causes a silent return of the empty string. Non-`exec:` tokens continue through the existing `context.getOrDefault` lookup unchanged. The the analysis-diff confirms that `TemplateEngine.expand` gained the `Exec` effect, and because the call chain above it is unchanged, that effect propagates transitively to every caller: `Page.renderToken`, `Page.render`, `RenderController.renderOne`, `RenderController.renderMany`, `RenderReport.buildAll`, and `Main.main` all now carry `Exec`. Reviewers should be aware that any code path reaching `expand` can now spawn arbitrary subprocesses depending on template input — this is an intentional capability expansion but means that untrusted templates must be sanitised upstream before being passed to the engine. The deprecated single-string `Runtime.exec` overload is used; if the project targets JDK 18+ seriously, switching to the `ProcessBuilder` API or the array-form overload would silence the deprecation warning without changing behaviour.
